# 전장 데이터와 시험 규칙

## 실제 파일과 생성

`daeyaseong.recipe.json`이 지형 사각형, 영역, 오브젝트, 출현점, 두 시점의 원본이다. `node map-tools/generate-maps.mjs`를 `munmu/manual`에서 실행하면 이 디렉터리의 모든 `*.recipe.json`을 읽고 목록까지 함께 갱신하며, `maps/silla-1-1.json`, `maps/baekje-1-3.json`이 결정적으로 생성된다. 결과는 8×36 타일 전부를 포함한다. 브라우저에서 편집하여 저장한 파일은 별도 JSON이며 원본 레시피나 서버를 자동 변경하지 않는다. 생성 도구를 다시 실행하면 생성 파일을 덮어쓴다.

`maps/manifest.json`은 실행 시 읽은 레시피에서 생성한 맵만 나열하며 화면의 선택 목록도 이 파일을 읽는다. 특정 레시피 파일만 인자로 넘겨 실행하면 목록도 해당 파일의 결과로 다시 작성된다. 다른 106판은 격자 데이터가 없다. 지형과 배치, 폭, 수치는 테스트 제안이고 실제 드라마 대본이나 엔진 동작 검증 완료가 아니다.

## 좌표와 판단

- (0,0)은 왼쪽 위, x는 오른쪽, y는 아래. 배열은 `tiles[y][x]`. 가로 8칸, 길이 36칸인 시험 맵이다. 1칸=1월드 단위는 임시 제안이며 미터 환산과 실제 유닛 폭·동시 통과 수는 미정이다.
- JSON의 `terrain`과 `elevation`은 타일마다 있고, 지형 종류별 통행 가능 여부·비용·시야는 JSON의 `terrainTypes`에 함께 기록한다. 실제 게임 엔진에서도 동일 필드를 읽어 구현해야 한다.
- `objects`는 `prototypeId`로 기존 오브젝트 도감 ID를 참조하고, 좌상단 anchor와 사각 footprint, 충돌/시야/파괴/문 상태를 기록한다. 이미지 시안만 있으며 3D 자산은 아직 없다.
- 점유 위치·출현점·구역 및 양 진영의 임무/출현점은 JSON에 기록한다. `mission.winConditions`, `loseConditions`, `events`, `counters`는 승패·웨이브 사건의 데이터 초안이다. 전투 상태 기계나 이벤트 실행기는 구현하지 않았으며, 백제 제한 시간은 미정이어서 null이다. 맵 차원 검사는 `map-engine.js`의 `validateMap`; JSON Schema 외에 행 길이, 경계, 겹침, 출현점 검사가 필요하다.
- 이동 시험은 한 칸 점유, 4방향 Dijkstra와 지형별 비용. 닫힌 성문·벽·물은 막고 열린/파괴된 성문은 통과한다. 다중 칸 부대, 기병 크기, 이동 중 동적 충돌은 미구현이다.
- 공격 시험은 타일 중심 좌표 간 유클리드 거리와 2D 슈퍼커버 시야다. 2.5칸처럼 소수 사거리를 지원하고 대각선 모서리 접촉 시 양쪽 칸을 검사한다. 목표 칸의 장애물은 공격 대상으로 가정해 시야 검사에서 제외한다. 숲·벽·닫힌 성문은 시야를 막고, 범위 내이면서 시야가 비어야 공격 가능이다. 시작/목표 위치의 실제 유닛 존재·공격 유형·파괴체력·피해·쿨다운은 아직 계산하지 않는다.
- 높이는 데이터로 보존하지만 고저차·성벽 위 배치·곡사·사거리 보정 판정은 구현되지 않았다. 해전·수공·문 파괴 트리거·공격 애니메이션·전체 부대 충돌도 설계/검증이 더 필요하다.

검사: `node --test map-tools/map-engine.test.mjs`. 게임 엔진에 그대로 연결된 완성 기능은 아니다.
