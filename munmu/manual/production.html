MUNMU / PRODUCTION MANUAL · 2026.11

선택한 영웅으로
전장을 지키고 돌파한다

대본·시제품·대화에서 정한 게임의 방향과 시각 기준을 한데 모은 작업 문서. 인물 이미지는 사용자가 괜찮다고 확인한 디자인 방향을 기준으로 삼고, 실제 제작 결과와 미검증 계획은 구분한다.

지금의 결론

시득의 맨발은 제공된 원본 명세의 개별 설정이다. 전군 공통 규칙이 아니다. 영웅·병사 이미지는 제작 검토용 2D 시안이며 3D 모델이나 바로 쓸 수 있는 동작은 아직 없다. 인물 간 비율은 서로 일치하지 않아 공통 3D 기준체를 이용한 보정이 필요하다. 무기를 손에 연결해 싸우는 게임은 구현할 수 있고, Meshy 동작을 재사용하되 무기·양손·판정은 별도로 검수한다.

확인된 방향

영웅 최대 3명과 각 기술 2개. 신라 청색·은백·천마, 고구려 흑색·청룡, 백제 어두운 갑옷·금빛 봉황, 당 적색·주작. 백제·고구려 플레이와 통일 경로.

제공 자료

9장·36개 전투의 대본, 시제품, 인물·병종 아트 명세. 시득 맨발은 원본 인물 명세에 기재.

시험 제안

자원·웨이브·영웅 등급·수치, 인물 문장 배치와 분기별 상세 전투는 플레이 검증 전 제안.

실제 검증 대기

Meshy 모델·리깅·무기 결합·동작, 엔진, 전 스테이지 밸런스와 배우 유사성.

FOUR FACTIONS / 2026.11 NEW DIRECTION

색과 상징으로 읽히는 네 진영

사용자 확정 게임 기준. 깃발과 병사의 장비에 같은 진영 표식을 쓴다. 아래 장수는 최신 색 기준의 단독 T포즈 초안이며, 영웅별 개인 문장과의 배치는 추가 검토한다. 주색과 표식은 게임용 디자인이며 유물에서 확인된 국가 군복·국장이라는 뜻은 아니다.

백제 봉황은 황색·긴 꼬리 실루엣, 당 주작은 적색·넓게 펼친 불꽃 날개를 게임상 구분안으로 제안한다. 병사 얼굴의 단순화는 시안마다 일관성 검수가 더 필요하다. 기존 남청·적갈 등 37개 시안은 보관하고, 새 색을 적용한 영웅 13종과 병사 24종을 별도로 제작했다. 장비 분리와 각 개인 문양은 재검수한다.

01 / GAME LOOP

출전에서 전투, 성장까지

1영웅·부대 편성

초반 1명, 진행하며 2명과 3명으로 확장. 해금 위치는 제안값.

2무기와 장비

무기 공격력·속도·거리, 갑옷 체력·방어, 말의 이동·방어를 비교한다.

3전장 지휘

영웅을 선택해 자유 이동. 영웅별 자동 이동과 자동 기술은 각각 켜고 끈다.

4결과와 성장

전투 안의 임시 강화와 전투 밖의 영구 성장을 구분한다.

수성

성벽 궁병은 자동 배치·사격하고, 선택한 영웅이 성문과 위협을 막는다. 해당 판에서 허용한 병력을 자원으로 추가한다.

공성·복합

선택한 병력이 자동 진군하고 자원으로 증원한다. 산길 → 강 → 성문처럼 구역별 목표·이동·전환 조건을 따로 지정한다.

기본 공격은 자동. 자동 이동 중 직접 이동은 수동 입력이 우선하며 자동 복귀 지연은 2초를 시험 제안한다. 선택되지 않은 수동 영웅도 제자리에서 사거리 내 적을 공격한다.

02 / MESHY + WEAPONS

무기를 들고 움직일 수 있을까?

가능하다. 다만 캐릭터의 동작과 무기 모델을 결합하고 손 위치·타격을 맞추는 과정이 필요하다. Meshy의 동작 목록에 검·활·도끼 동작은 있지만, 현재 우리 모델에 무기까지 자동으로 완벽하게 붙는지는 직접 시험 전이다.

1인물

무기 없이 팔·다리·손가락이 보이는 1인 T포즈 이미지 → 3D → 리깅.

2무기

검·창·방패·활·화살·도끼를 별도 모델로 준비. 손잡이 위치와 방향을 기록.

3결합

손 뼈 아래에 무기 부착점(grip)을 두고 모델의 손잡이를 맞춘다.

4움직임·판정

동작을 적용하고 맞는 순간에 판정·효과·소리를 실행한다.

A포즈와 T포즈 · Meshy 기준

Meshy는 A포즈와 T포즈를 지원하지만 이 프로젝트는 팔과 망토의 간섭을 줄이기 위해 T포즈를 기준으로 선택했다. Image to 3D의 Pose에서 자세를 선택할 수도 있다. 현재의 앞·뒤 병렬 그림은 디자인 검토용이며, 모델 입력용 1인 이미지와 실제 리깅 성공을 뜻하지 않는다. 먼저 한 캐릭터를 단독 정면 이미지로 만들고, 팔·겨드랑이·손·다리 분리와 관절 마커, 달리기·공격 시 갑옷 변형을 확인한다. Meshy 공식 리깅 가이드 ↗

부착점은 게임 엔진의 자식 노드나 Blender의 본 연결 등으로 만들 수 있다는 구현 방향이다. 아직 특정 엔진이나 사용 방식은 결정하지 않았다. 양손은 두 번째 손에 역운동학(IK)을 쓰거나 동작을 수정하는 방법을 비교한다.

그럼 애니메이션을 다 직접 만드나?

먼저 재사용

04 / HERO ROSTER

영웅별 무기·기술·등급과 새 시안

백제·고구려 신규 영웅 10명과 전체 시안 보기 ↗

13종은 법민과 문무왕의 두 시기 외형을 포함한 시안이다. 두 외형은 같은 인물이다. 영웅별 기술은 모두 두 개이며 등급·조합은 제안값이다. 아래 이미지는 새 진영색을 적용한 앞뒤 시안이다. 등급은 테스트 제안이며 이미지를 누르면 원본을 볼 수 있다.

문무와 법민은 동일 인물이라 동시 편성 금지 방향을 제안한다. 시득의 맨발은 원본 기획의 캐릭터 설정이지 신라 수군 전체의 고증이 아니다. 다른 맨발 표현은 이미지별 재검수한다.

신라 대본 36개와 삼국의 분기

아래 제목과 정보는 제공 대본의 목록이다. 추가 스테이지는 가능하다. 36개 판의 개별 웨이브·수량·보상·완성 지도는 아직 설계·검증되지 않았다. 기존 화면의 공통 웨이브 숫자는 자리표시 제안이다.

08 / BUILD ORDER

한 명, 한 자루, 한 판으로 먼저 검증

  1. 1인용 이미지 준비. 승인된 시안을 기준으로 앞면과 뒷면을 한 장에서 나란히 쓰지 않고 각각 분리해, 신체·손이 가려지지 않는 모델 입력을 준비한다. 정면/후면 형상이 맞는지 확인한다.
  2. 모델 한 명 + 무기 한 자루. 인물은 무기 없이 생성하고 검/창 등은 별도 생성·정리한다. 손·팔·다리 분리, 갑옷 관통, 문장의 앞뒤 재현과 손잡이 위치를 확인한다.
  3. 리깅과 기본 클립. T포즈의 텍스처 모델로 리깅하고 idle·walk·run·attack·hit·dead 후보를 실제 결과물에서 확인한다. 손·팔·어깨·갑옷이 찌그러지는지 클립 전체를 살핀다.
  4. 무기·명중 검증. 손 본에 무기를 붙이고 움직이는 동안 손잡이의 이탈, 두 손 간격, 모델 관통과 타격 시점·사거리·데미지를 확인한다. 활은 두 손과 화살 발사를 별도 시험한다.
  5. 수성 1판과 공성 1판. 영웅 전환·개별 자동 설정·적 저지·부대 추가 출격·승패·보상까지 하나의 플레이 흐름으로 실행한다. 공성은 여러 구역의 전환 조건을 검증한다.
  6. 확장 전 결정. 검/창/활/기마 각각의 대표 시험 결과, 모델 수정 난도·기기 성능·2D 전장과 3D 인물 결합, 도구와 팀 역량을 비교해 엔진을 선택한다.

영구 성장과 전투 내 성장

영웅 레벨·장비·기술 강화는 전투 밖, 경험치로 고른 임시 강화는 한 판 안에서 관리한다. 수치 합산·상한은 제안 후 테스트한다.

실패 상황

자동·수동 기술 동시 요청, 영웅 전투불능 시 전환, 재화 부족·정원 초과, 무기 교체 중 공격, 말·기수 분리, 루프 경계와 경로 실패를 시험한다.

Meshy 키 제공이나 유료 생성은 아직 진행하지 않았다. 위 순서는 구현 계획이며 완성된 검증 결과가 아니다.
